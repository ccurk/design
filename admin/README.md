# 活动搭子 · 运营后台（admin/）

给运营同学用的网页后台：确认撮合、处理举报和待审内容、管理局、处理信用和申诉、维护小程序首页的轮播图和热门标签。

纯静态页面，**不需要构建**：Vue 3（仓库里的本地文件）+ 浏览器原生 ES module，由 `server/` 直接托管在 `/admin/`，接口在同源的 `/api/admin/*`。

## 怎么打开

1. 启动后端（第一次先装依赖、写演示数据）：

   ```bash
   cd server
   npm install
   npm run seed     # 清空数据库并写入演示数据；生产环境不要跑
   npm start        # 默认 http://localhost:3000
   ```

2. 浏览器打开 <http://localhost:3000/admin/>（打开 `http://localhost:3000/` 也会跳过来）。

后台页面和接口同源，不用另外配跨域或代理。页面用 hash 路由（`/admin/#/matching`），地址栏的路径永远是 `/admin/`，所以 `./app.js` 这类相对路径不会找错；从 `/admin/users` 这样的地址打开也会自动跳回 `/admin/#/users`。

## 登录

- 密码就是服务端的环境变量 `ADMIN_PASSWORD`；开发环境没设置时默认 `admin123`，生产环境必须设置。
- 同一个 IP 15 分钟内输错 10 次，会被锁到这 15 分钟结束。
- 登录后 token 存在浏览器的 localStorage（`dazi.admin.token`），7 天有效。任何接口返回 401（过期、被清掉）都会自动清掉 token 回到登录页，重新登录后回到原来那一页。
- 左侧菜单最下面是「退出登录」。

## 各页面做什么

### 概览 `#/dashboard`

- 今天的数字：今日新用户、今日新意向（都和昨天比，「比昨天 +3」）、等你确认的局（点了去撮合池）、待处理举报和待审内容（点了去审核）、近 7 天履约率（和再往前 7 天比，「比前 7 天 −2 个百分点」）。
- 「近 7 天」是滚动的最近 7×24 小时（不是自然周），所以写「近 7 天 / 前 7 天」，不写「本周 / 上周」。
- 近 7 天成局数：柱状图，鼠标悬停或键盘聚焦柱子能看到具体数字；「表格」可以换成表格看同一组数据。
- 等你确认的局、待处理的举报（群聊里的举报会写是哪个局的群聊）、需要留意的事（申诉、受限的人和原因、等了一天以上还没配上的人、近 7 天放鸽子次数和前 7 天比）。
- 每 5 分钟自动刷新一次。

### 撮合池 `#/matching`

系统先配好，后台过目确认（规则见 `docs/api.md` 3.2）。

- **待确认**：每个方案的匹配度、成员（履约率、每个人有空的时间如「下午」「14:00–17:00」、社交节奏、新人、信用一般）、大家约好的人数（比如「3–5 人」，接口的 `minSize` / `maxSize`）、有人填了具体时间段时大家都有空的时间（「大家都有空：14:00–16:30」）、为什么配到一起、风险提示。
  - **确认成局**：可以改标题、日期、开始时间（精确到分钟，默认用接口算好的 `defaultStartAt`）、时长、地点、集合点、费用方式和预计每人费用、人数上限（不能少于已配的人数，也不能超过大家约好的最多人数；多出来的名额系统会从池子里补邀）→ 给每个人发「撮合成功」，各自点「加入」才算数。有成员这个时间已经有别的局时，服务端会拒绝（「和 X 已加入的「…」时间重叠了」），原因写在表单里。
  - **调整成员**：把人移出（回到池子），或把池子里想做同一件事的人加进来，匹配度和风险会重新算。人数少于大家约好的最少人数（或多于最多人数）时「确认成局」不能点，旁边会写还差几个人；服务端也会拒绝。
  - **退回**：必须选一个原因，可以补充说明（只有后台能看到）；这些意向回到池子，同样这几个人同一天的同一件事不会再被配到一起。
- **已发邀请**：还在「邀请中」的撮合局：几个人加入了、截止时间、每个人的状态（待回复、已加入、换了一批、没回复，已过期……）。
  - **提醒还没回复的人**：用微信服务通知提醒还没点「加入」的人，完成后提示提醒了几位（都回复了会直接说）。
- **已退回**：退回过的方案和原因，最近退回的在最前面。
- **立即撮合一次**：马上跑一次撮合（平时每 5 分钟自动跑）。
- **自动成局**（默认关闭）：打开后，每次撮合都会检查所有待确认的方案（包括打开之前就在的），匹配度达到门槛（≥ 85 / 90 / 95）又没有任何风险提示的，下次撮合时直接成局。
- **还在等的人**：撮合池里的意向（含时间，比如「周日 14:00–17:00 · 骑行」）和等了多久，第一次参加的人标「新人」，超过一天会标出来。调整成员时，候选人的时间按「时间窗至少重叠 60 分钟」判断对不对得上。

### 审核与举报 `#/moderation`

- **举报**：原因、类型、时间、匿名的举报人编号、被举报的内容和它在哪里（比如「来自『桌游夜 · 新手友好』群聊」「评论在动态『……』下面」）、举报人补充和截图、被举报人的信用和被举报次数（能跳到「用户与信用」看信用记录）。
  处理方式五选一：驳回 / 警告 / 删除内容 / 限制 7 天 / 封号（封号要再确认一次）。处理后举报人会收到结果通知。
  - **给 TA 的说明**（选「警告」「删除内容」「限制 7 天」「封号」时出现，选填）：会发给被处理的人，替换默认说明（输入框下面写着不填会发什么）；删除内容时作者也会收到通知。不能写手机号、微信号或网址，写了服务端会拒绝，提示在输入框下面。
  - **备注**（选填）：只存在后台，不会发给任何用户。
  - 已经封号的人不能再「限制 7 天」或「封号」（按钮是灰的）；如果别人刚处理过，会提示服务端给的原因并刷新。
- **动态待审**：被内容审核拦下的动态（联系方式、广告等），照片是缩略图，点开看大图。通过就发出来；不通过要选原因，作者会收到通知。
- **局待审**：用户发起的、命中内容审核的局（含标签、谁可以报名和照片）。通过就发到广场；不通过要选原因，发起人会收到通知。
- 举报截图、动态和局的照片都可以点开看大图：左右方向键切换，Esc 关闭。

### 局管理 `#/events`

- 搜标题 / 地点，按状态（招募中、邀请中、已成局、待审核、已结束、已取消、未通过）和来源（撮合、用户发起、平台）筛选，筛选都由服务端做：「已结束」= 已经过了结束时间的招募中 / 已成局的局，「招募中」「已成局」不含已结束的。表格太宽时在自己的框里横向滚动。
- 列表里每个局有封面（第一张照片，没有照片用标签的插画）、标签、来源，限性别的写着「只限女生 / 只限男生」。
- 查看详情：照片（点开看大图）、时间和时长、地点（名字 + 详细地址）和集合点、费用、谁可以报名、最晚退出时间（过了会写「已过，不能再退出」）、成员和各自的状态（包括「邀请过期没回复」）、还差几人满员、最近的群聊、被举报次数，以及 AA：谁记的、一共多少、写了包含什么、每人多少；接口返回了转账明细（`aa.transfers`）时，再列出每一笔转账的状态（还没转 / 说已转，等确认 / 已确认收到）。邀请中的撮合局还会显示几个人加入了、几个人没回复、截止时间，可以「提醒还没回复的人」。
- **取消这个局**：要选原因，会通知所有成员，不扣任何人的信用；撮合局的意向放回撮合池。
- 待审核的局可以直接通过 / 不通过。
- **发起平台局**：直接发到广场，没有发起人，满员自动成群。要填标题、标签（点热门标签，或者自己写一个；分类按标签自动定）、日期和开始时间（精确到分钟）、时长、地点（可以再写详细地址）、集合点、人数上限、费用、谁可以报名（不限 / 只限女生 / 只限男生）、最晚退出时间（开始前 2 / 6 / 12 / 24 / 48 小时，已经过了的选项不能用）、照片（最多 9 张，第一张当封面）、介绍。

### 用户与信用 `#/users`

- **全部用户 / 受限中**：搜昵称或手机尾号，按信用等级（良好、一般、受限、已封号）筛选（「受限」不含已封号的人）；表格里有履约率、到场、临时鸽、放鸽子、被举报次数，受限 / 封号的人名字下面写着原因。
- **用户详情**：信用数字、信用记录（会拉低履约率的记录可以撤销：履约率马上重算并通知本人，这条记录上待处理的申诉也会自动通过）、账号处理（限制 7 天 / 解除限制 / 封号 / 解封），受限 / 封号时写着「受限到 … · 原因」「已封号 · 原因」。
- **申诉**：用户对某条信用记录的申诉。「系统找到的证据」列出 TA 开场前 72 小时内在那个局的群里说的话（「开场前 N 小时」），下面按 `docs/api.md` 3.1 的规则给一句提示：提前 24 小时以上说了 → 建议通过；24 小时内才说 → 应记「临时鸽」而不是「放鸽子」；没找到 → 没找到 TA 提前说过。通过 = 撤销那条记录并通知 TA；驳回要写一句回复，会发给 TA。

### 内容运营 `#/content`

- **首页轮播**：小程序首页顶部的轮播图，按顺序展示。每张有图片（点开看大图）、标题、副标题、点了去哪（某个局 / 广场 / 发起局 / 动态 / 社区公约 / 不跳转）、是否展示的开关。
  - 添加 / 编辑：上传图片（jpg / png / gif / webp，≤ 5MB，走 `POST /api/admin/upload`），「某个局」要搜标题或地点选一个（只能选广场上看得到的局，撮合局不行）。
  - 上移 / 下移调顺序；关掉开关就不展示（不删）；删除要再确认一次。
- **热门标签**：大家选「想做的事」、发起局时先看到的标签，按这里的顺序。
  - 上移 / 下移、移出热门（标签本身还在，提示条上可以「撤销」）。
  - 添加：名字（1–8 个字，只能用文字、数字、空格和 · - _，会过内容审核；服务端拒绝的原因写在输入框下面）、分类、插画（局没有照片时当封面，预览图在 `admin/illustrations/`）。已经有的标签会直接加到热门。
  - 大家最近在用的标签：近 30 天的使用次数排前面，不是热门的可以「加到热门」。

## 文件

```
admin/
  index.html            页面入口
  app.js                入口：登录守卫、左侧菜单 + 内容布局、挂载
  style.css             样式（颜色、圆角、尺寸来自 design/admin/*.dc.html）
  favicon.svg
  src/
    api.js              api()：前缀 /api、JSON、Bearer token；失败抛出 { code, message }；401 回登录页
    router.js           hash 路由
    store.js            菜单上的待办角标
    format.js           北京时间格式化、各种状态的中文和配色
    ui.js               通用组件：菜单、提示条、标签页、开关、计数器、加载状态、缩略图 + 看大图、上传图片、封面……
    pages/              七个页面：login、dashboard、matching、moderation、events、users、content
  illustrations/        十张插画（从 design/illustrations 复制），标签和局的默认封面
  vendor/
    vue.esm-browser.prod.js   Vue 3.5.13（带模板编译器），MIT 协议，见 vue.LICENSE.txt
  tools/
    e2e.mjs             端到端测试
```

- 不访问任何外部资源（没有 CDN、没有 Google Fonts），国内网络也能正常打开。字体：PingFang SC / Noto Sans SC / 微软雅黑 / 系统字体。
- 所有时间按北京时间（Asia/Shanghai）显示；表单里填的日期和时间也按北京时间理解。
- 用户写的内容一律当文本显示（不用 `v-html`）；用户上传的图片地址只放行 http(s) 和本站相对路径。
- 浏览器：近两年的 Chrome / Edge / Safari / Firefox（需要支持 ES module）。
- 手机宽度也能用：菜单折到页面上方，宽表格在自己的框里横向滚动。
- 升级 Vue：在一个临时目录里 `npm pack vue@<版本号>`，解压后把 `package/dist/vue.esm-browser.prod.js` 拷到 `vendor/`。

## 端到端测试

测试会改数据（确认 / 退回方案、处理举报、撤销信用记录、上传图片……），请用一个临时数据库、临时上传目录单独起一个服务，**每次跑之前重新 seed**：

```bash
cd server
export DB_PATH=/tmp/admin-e2e.db UPLOAD_DIR=/tmp/admin-e2e-uploads   # 上传的测试图片也放到临时目录
node --no-warnings scripts/seed.js
PORT=3100 node --no-warnings src/index.js &

cd ..
node admin/tools/e2e.mjs                       # 默认 http://localhost:3100，密码 admin123
node admin/tools/e2e.mjs http://localhost:3100 admin123 --shots /tmp/admin-shots   # 顺便截图
```

- 需要 Playwright 和 Chromium（`require('playwright')` 能用就行）。上传用的测试图片是脚本自己画的 PNG，不需要准备文件。
- 测试会用开发接口 `/api/auth/dev-login` 造几条待审动态（一条带照片）、几个能被撮合的意向（有两个填了具体时间段），也会用它以用户身份看收到的通知、报名局，所以服务端不能是 production 模式。
- 测试内容：
  - 登录（没填、输错、正确）；390px 手机宽度下每一页（含展开的表单、详情、申诉证据、轮播图、热门标签）都不横向滚动。
  - 概览：数字、「比昨天」「比前 7 天」和接口一致，举报写着是哪个局的群聊，柱状图和表格。
  - 撮合池：移出一个新人后人数少于约好的最少人数 → 「确认成局」不能点、接口也返回 400，池子和候选人里标着新人，加回来后恢复；确认成局（人数上限不超过约好的最多人数）；「提醒还没回复的人」并确认被邀请的人收到了提醒；退回；立即撮合；自动成局开关；填了具体时间段的方案写着「大家都有空：14:30–17:00」、成员写着各自的时间、集合时间默认是接口的 `defaultStartAt`，成员这时已经报了同一时间的局 → 确认被拦（409），原因写在表单里。
  - 审核：举报详情写着来自哪个局的群聊；警告时「给 TA 的说明」带微信号会被拦，正常的说明 + 备注提交后，被举报的人收到的提醒正文就是说明，任何通知里都没有备注；带照片的动态（缩略图、点开看大图）通过 / 不通过；局不通过。
  - 局管理：来源、关键词筛选，「已结束」由服务端 `status=ended` 筛；详情里的 AA（谁记的、一共多少、包含什么、每人多少；接口有 `aa.transfers` 时还核对每笔转账的状态，没有时在结尾提示）；邀请中的撮合局的进度和提醒；发起平台局（热门标签 / 自己写的标签、只限女生、开始前 6 小时最晚退出、精确到分钟的开始时间、详细地址、两张照片；不是图片的文件在本地就挡掉），接口和详情里都对，照片点开看大图、方向键切换、Esc 关掉后焦点回到缩略图；取消有人报名的局。
  - 内容运营：轮播图列表和接口一致、点开看大图；添加（没传图不能保存、上传图片、链接到刚发起的平台局）后小程序首页 `GET /api/home` 马上有；关掉展示后首页就没有；上移、编辑、删除（要确认）。热门标签：审核不过（422）、太长（400）的原因写在输入框下面；添加后排在最后，小程序的 `GET /api/tags/hot` 也变了；上移、移出热门再撤销、从「大家最近在用的标签」加到热门。
  - 用户：撤销信用记录看履约率变化、本人收到通知；限制（显示原因）/ 解除；封号（显示原因）→「已封号」筛选只有 TA、「受限」不含 TA → 解封；申诉的证据和提示、通过。
  - 登录过期回到登录页；退出登录。
  - 全程不能有控制台报错和失败的请求（故意触发的 400 / 401 / 409 / 422 除外，图片加载失败也算问题）。失败时退出码不为 0。
- 可选：`E2E_VUE_DEV=<Vue 开发版 vue.esm-browser.js 的路径>`，测试时换成 Vue 开发版，模板里写错的字段（`[Vue warn]`）也会算失败。

## 和设计稿不一样的地方

- 申诉里的截图：申诉没有图片，只显示 TA 写的话和系统找到的群聊证据。
- 确认成局 / 发起平台局里的自由文字「费用说明」：接口只有费用方式和预计费用，所以做成「费用方式 + 预计每人 ¥」。
- 概览的「本周履约率」「比上周」写成「近 7 天履约率」「比前 7 天」：接口按滚动的 7×24 小时算，不是自然周。
- 「内容运营」页面没有设计稿，沿用其他页面的样式（卡片、选择小块、开关、缩略图）。
