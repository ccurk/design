# 微信小程序上线文档

本文档只讲「怎么把这个小程序正式发布到微信线上」。服务器部署、环境变量、冷启动数据等见
[`docs/go-live.md`](./go-live.md)，这里不重复，只在需要处引用。

> 代码结构：`server/`（Node + Express API）、`miniprogram/`（无构建微信小程序）、`admin/`（运营后台）。

---

## 0. 一句话流程

注册并选对主体/类目 → 服务器上生产（HTTPS + 备案域名）→ 配置小程序服务器域名 → 改正式
AppID 和接口地址 → 开发者工具上传 → 公众平台提交审核 → 通过后发布。

---

## 1. 前置条件（缺一不可）

### 1.1 账号与主体
- **主体类型**：强烈建议**企业/个体工商户主体**，不要个人主体。个人主体限制很多：
  - 不能用微信支付、不能用 `web-view` 打开外部网页、部分类目（含社交）受限。
  - 本项目「商务合作 → 跳外部广告页 / 跳其它小程序」等后续能力，个人主体做不了。
- **小程序类目**：本产品是**陌生人线下兴趣社交**。注册时类目要如实选（社交类往往需要补充资质，
  且审核更严）。类目选错会被驳回或后续被责令整改。

### 1.2 资质与合规（社交类重点，务必提前准备）
- **ICP 备案**：服务器域名必须完成 ICP 备案（经营性内容还需 ICP 许可证）。
- **《小程序用户隐私保护指引》**：在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」里填写并提交，
  **收集的每一项信息都要声明**（手机号、地理位置、相册、昵称头像、紧急联系人等）。不填无法发布。
- **内容安全**：UGC（动态、资料、局信息、申诉文本）**上线前必须接真实内容安全**。
  当前代码里 `msgSecCheck` 是占位，必须换成真实调用（文本 `security.msgSecCheck`、图片
  `security.imgSecCheck`）。这是社交类最高频的驳回与封禁原因。
- **未成年人保护 / 实名**：按微信要求配置；社交类通常要求实名或手机号绑定（本项目已有手机号认证）。
- **举报与处置闭环**：举报入口（已有）、后台审核、封禁/受限（已有信用与封禁体系）——审核时会检查。

### 1.3 线上服务（见 go-live.md）
- 生产环境跑起来，`NODE_ENV=production`、`ADMIN_PASSWORD` 已设、`PUBLIC_BASE_URL` 指向 **https 域名**。
- HTTPS 证书有效（微信只认 https，且不认自签名）。
- 数据库持久化 + 定时备份。

---

## 2. 配置小程序的服务器域名

公众平台 →「开发管理 → 开发设置 → 服务器域名」，把生产域名加进去：
- **request 合法域名**：`https://你的域名`
- **uploadFile 合法域名**：`https://你的域名`（头像、图片上传）
- **downloadFile 合法域名**：`https://你的域名`（图片/封面）

> 每月可修改次数有限，别频繁改。域名必须是**已备案**的、**https** 的、**不带端口/路径**的根域名。

---

## 3. 小程序代码改成「正式」

1. **AppID**：`miniprogram/project.config.json` 里的 `appid` 改成**正式小程序 AppID**（不要测试号）。
2. **接口地址**：确认请求的 baseURL 指向**生产域名**（排查 `miniprogram/utils/request.js` /
   `config` 里是否还有 `localhost` / `127.0.0.1` / 内网 IP）。
3. **关闭调试旁路**：开发者工具「详情 → 本地设置」里，**取消勾选**「不校验合法域名、web-view、TLS」。
   如果勾着能跑、取消后报错，说明域名没配好，回到第 2 步。
4. **版本号**：在 `project.config.json` 或上传时填写，遵循语义化（如 `1.0.0`）。

---

## 4. 真机验证（提交审核前必做）

在微信开发者工具里：
1. **预览**：扫码在自己手机上走一遍核心链路。
2. **真机调试**：重点验证——登录/手机号授权、撮合发起、广场加入、群聊、AA、上传图片、
   片区选择（`<picker>`）、轮播广告落地页、信用记录、安全设置（报平安/紧急联系人）。
3. **上传体验版**：开发者工具「上传」→ 公众平台「版本管理 → 开发版本 → 选为体验版」，
   加几个体验成员，覆盖不同机型（iOS / 安卓、大屏 / 小屏）跑一轮。

### 发布前自检清单
- [ ] 所有接口走生产 https 域名，取消「不校验合法域名」后仍正常
- [ ] 内容安全 `msgSecCheck` / `imgSecCheck` 已接真实接口
- [ ] 隐私保护指引已提交，覆盖所有收集项
- [ ] 举报 / 拉黑 / 封禁闭环可用
- [ ] 冷启动数据已就位（运营号 + 运营局，见 go-live.md 的 `npm run seed:cold`）
- [ ] 后台（admin）能登录、能审核动态 / 带队申请 / 配轮播
- [ ] 轮播广告的「商务合作」联系方式已填成真实的（`miniprogram/pages/me/me.js`）
- [ ] 标题等展示无 `undefined`（历史数据已被 `repairBadTitles` 修复，重启服务端生效）

---

## 5. 上传 → 提交审核

1. 开发者工具「**上传**」：填**版本号** + **项目备注**（写清本次改动，审核人员会看）。
2. 公众平台「**版本管理 → 提交审核**」：
   - 选**功能类目**（与实际一致）。
   - 填**审核涉及的页面**和**功能描述**。
   - 提供**测试账号**（审核员要能登录体验全部功能，含手机号登录的测试通道）。
   - 勾选/填写隐私相关项。
3. **审核时长**：一般 0.5~2 个工作日，社交类可能更久或被要求补充资质。

### 社交类高频驳回点（提前规避）
- UGC 没有有效内容审核机制 / 没有举报入口。
- 隐私信息收集未在指引中声明，或索取与功能无关的权限。
- 诱导分享、诱导关注（朋友圈/好友分享文案要克制）。
- 涉及交友但未做风险提示 / 未成年人保护不足。
- 类目与实际功能不符。

---

## 6. 发布

审核通过后，「版本管理 → 审核版本 → **发布**」：
- 可**全量发布**，也可**分阶段发布（灰度）**：先放一部分用户，观察崩溃/反馈再全量。首次上线建议灰度。
- 发布后线上即生效，无需用户更新（小程序特性）。

---

## 7. 上线后（运营与监控）

- **运营**：后台配轮播/广告、维护热门标签；保证每天自动发布的**运营局有真人到场**（冷启动诚信）。
- **监控**：公众平台自带「运维中心」看错误率、性能；服务端加日志与告警（见 go-live.md）。
- **客服与处置**：联系客服入口（已有）、违规内容及时处理（内容安全回调 + 后台审核）。
- **订阅消息**：如要做 push（留存关键），需在公众平台申请模板并在合适时机 `requestSubscribeMessage`
  （当前未接，属上线后增强项）。

---

## 8. 还没做、但上线前建议补齐（来自历次评审）

1. **内容安全**真接（`msgSecCheck` / `imgSecCheck`）——社交 UGC 过审硬门槛。
2. **报平安兜底**真接（紧急联系人目前只写日志）——线下安全红线。
3. **运营局真人到场**——冷启动自动发的局要有人真带队。
4. **订阅消息 push**——留存。

前两项是上线前应完成的，后两项可上线后快速跟进。
