# iOS / Android App 上线文档

> **现状**：本产品目前是**微信小程序**（`miniprogram/`）+ Node 后端（`server/`）+ 运营后台（`admin/`）。
> **还没有原生 App。** 本文档是「把它发展成独立 App」时的上线指南：先定技术路线，再分别过 iOS、
> Android 的上架流程，最后是国内上架的硬资质。后端 API 基本可直接复用。

---

## 0. 第一步：定技术路线（决定后面所有工作量）

| 路线 | 说明 | 适合 |
|---|---|---|
| **uni-app**（推荐起步） | 一套代码编译到 iOS / Android / 小程序。**最大程度复用你现有小程序的页面与逻辑** | 想快、想和小程序共存、团队小 |
| **Flutter** | 一套 Dart 代码，双端体验好、性能强，但要重写 UI | 想要接近原生的体验、长期投入 |
| **React Native** | 一套 JS，生态大 | 团队熟 JS/React |
| **原生**（Swift + Kotlin） | 双端各写一遍，体验最好、成本最高 | 后期有钱有人、追极致体验 |

- **后端不用重做**：现有 `server/` 的 REST API（见 `docs/api.md`）App 端直接调。
- **建议**：先用 **uni-app** 把小程序逻辑迁成 App 快速上线，验证需求；跑通了再考虑 Flutter/原生重构。
- **审核更严**：App Store / Google Play 对**陌生人社交**审核远比小程序严（UGC、未成年人、安全、隐私），
  下面重点讲这些。

## 1. iOS 上线

### 1.1 账号与证书
- **Apple Developer Program**：公司账号 **$99/年**，需要 **D-U-N-S 编号**（公司邓白氏码，申请免费但要几天）。
- 证书链：**App ID**（Bundle ID，如 `com.yourco.caotai`）、**开发/发布证书**、**Provisioning Profile**、
  **APNs 推送证书/Key**（做推送要）。
- 用 Xcode 自动管理签名可省事，但发布证书建议了解清楚。

### 1.2 App Store Connect 建 App
- 填 **Bundle ID、App 名称、副标题、分类（社交 Social Networking）、关键词、截图、隐私政策链接**。
- **隐私营养标签（Privacy Nutrition Label）** + **隐私清单（PrivacyInfo.xcprivacy）**：如实申报收集的数据
  （手机号、位置、用户内容、设备标识等）及用途。
- **年龄分级**：陌生人社交通常 **17+**。

### 1.3 iPhone 全机型适配（你特别要求）

> 关于「iphone duo」：我按**「iPhone 全机型适配」**理解来写（刘海 / 灵动岛 / 安全区 / 各尺寸）。
> 如果你指的是某个具体机型或折叠屏，告诉我，我再补。

必做的适配项：
- **安全区（Safe Area）**：顶部**刘海 / 灵动岛（Dynamic Island，14 Pro 及以后）**、底部 **Home Indicator**。
  内容用 `safe-area-inset-*`（uni-app/RN）或 Auto Layout 的 Safe Area Guide，**别把按钮/标题顶到状态栏或底部横条下面**。
- **全尺寸覆盖**：从 **iPhone SE（4.7"，最小）** 到 **Pro Max（6.9"，最大）**。用**弹性布局**，不要写死像素。
  最小适配基准建议 iPhone SE。
- **屏幕密度**：准备 **@2x / @3x** 图片资源；图标、启动图按 Apple 要求的全套尺寸出图。
- **灵动岛 / 刘海遮挡**：顶部交互元素避开灵动岛区域；全面屏圆角别裁切内容。
- **深色模式**：适配 Light / Dark（你小程序已有深浅色 token，可复用设计）。
- **动态字体（Dynamic Type）**：支持系统放大字号，别让大字号撑破布局。
- **方向**：社交 App 一般**锁竖屏**（除非有视频/地图需要横屏）。
- **键盘遮挡**：输入框上推，避免被键盘挡住（撮合、发局、聊天、申诉都有输入）。

### 1.4 iOS 审核高危点（社交类最容易被拒）
- **UGC「零容忍」机制（Guideline 1.2）**：必须有 ①内容过滤 ②**举报** ③**拉黑/屏蔽用户** ④**封禁** ⑤
  **24 小时内处理并移除违规内容和用户**的承诺与能力。你后端已有举报/拉黑/封禁/信用体系，App 端要把入口都接出来。
- **App 内删除账号（强制）**：必须提供**应用内注销账号**入口，否则必被拒。
- **登录方式**：若提供任何第三方登录（微信/Apple/Google），**必须同时提供 Sign in with Apple**；
  若**仅手机号/短信登录**可豁免。
- **ATT（App Tracking Transparency）**：如涉及跨 App 追踪，要弹 ATT 授权。
- **权限用途说明**：`Info.plist` 为**定位、相册、相机、通知、通讯录**等写清楚用途文案（`NS...UsageDescription`），
  文案要具体，泛泛描述会被拒。
- **线下见面安全**：交友类建议内置**安全提示 / 风险告知**（你已有报平安、紧急联系人，接出来是加分项）。
- **EULA / 用户协议**：UGC 社交必须有用户协议，明确禁止令人反感的内容与行为。

### 1.5 打包 → 测试 → 提交
1. Xcode **Archive** → **上传到 App Store Connect**。
2. **TestFlight** 内测：先内部测试，再外部测试（外部测试也要过一次审核）。
3. **提交审核**：填审核信息、**提供可登录的测试账号**（审核员要能体验全部功能）、备注说明。
4. 审核时长一般 1~3 天；被拒会给 Guideline 编号，按条修复后回复/重交。
5. 通过后**发布**（手动发布或自动发布，可分阶段发布 Phased Release）。

## 2. Android 上线

> **国内关键差异**：Google Play 在中国大陆不可用。**国内用户主要走各安卓应用市场**
> （**华为、小米、OPPO、vivo、应用宝**等），这些必须**单独提交**，且对社交类**资质要求更硬**（见第 3 节）。

### 2.1 Google Play（面向海外 / 港澳台）
- **Google Play Console** 开发者账号：**$25 一次性**。
- **应用签名**：用 Play App Signing，保管好上传密钥。
- **包名**（applicationId，如 `com.yourco.caotai`）一旦上线不可改。
- **targetSdkVersion** 要满足 Play 的最低要求（每年抬高，按当年要求）。
- **数据安全表单（Data safety）**：如实申报收集/共享的数据，和隐私政策一致。
- **账号删除**：Play 同样**要求提供删除账号的途径**（App 内 + 网页入口）。

### 2.2 国内安卓市场
- 每个市场各自注册开发者、各自提交，审核规则不一。
- 普遍要求：**软件著作权证书、ICP 备案、隐私政策、应用权限说明、实名**；社交类常被要求**补充资质**
  （见第 3 节）。
- 建议用**聚合分发**工具统一管理多市场发版。

### 2.3 Android 适配要点
- **多分辨率 / 多密度**（mdpi~xxxhdpi）、**刘海屏 / 挖孔屏**、**手势导航栏**安全区。
- **深色模式**、**运行时权限**（定位/相册/相机/通知逐项动态申请 + 用途说明）。
- **后台/推送**：国内推送要接厂商通道（华为/小米/OPPO/vivo push）才能保证到达，不然杀后台收不到。
- Android 14+ 的前台服务、通知权限等新限制要遵守。

## 3. ⚠️ 国内 App 上架的硬资质（小程序没这么重，App 必须有）

这些是**国内安卓市场和 iOS 中国区**上架社交 App 的门槛，**提前几周就要启动**：
1. **软件著作权（软著）**：App 的著作权登记，几乎所有市场都要。
2. **ICP 备案**（网站/服务）+ 若经营性内容需 **ICP 许可证（EDI/ICP 经营许可）**。
3. **工信部 App 备案**：2023 年起**强制**，App 必须完成备案（通过云厂商或主体提交），否则会被下架。
4. **网络文化经营许可证（文网文）**：涉及互动社交/直播/UGC 运营的，很多市场会要。
5. **公安联网备案 / 等保测评**：平台类产品常被要求（等保 2.0）。
6. **实名制**：《网络安全法》要求后台实名（你已有手机号认证，够不够看类目要求）。

> 这几项**周期长、卡脖子**，决定你能不能上，建议**在写 App 代码的同时就并行去办**。

---

## 4. 上线节奏建议

1. **先把小程序跑稳、拿到真实用户与数据**（验证需求，成本最低）。
2. 并行**办资质**（软著 / ICP / 工信部备案 / 文网文）——这些不快。
3. 技术上**用 uni-app 复用小程序**先出 App MVP，走 TestFlight / 内测。
4. iOS 先过（规则清晰），Android 先 Google Play、再逐个铺国内市场。
5. 推送、深度链接、支付（如要）等增强项，上线后迭代。
