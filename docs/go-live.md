## 1. 架构与组成(单机部署)

| 部分 | 技术 | 部署方式 |
| --- | --- | --- |
| `server/` | Node.js ≥22.5 + Express + SQLite | 常驻进程(pm2 / systemd),放 Nginx + HTTPS 之后 |
| `admin/` | Vue 3,免构建 | **由 server 托管在 `/admin/`,无需单独部署** |
| `miniprogram/` | 微信原生,免构建 | 微信开发者工具上传、提交审核 |

- 数据:SQLite 单文件 `server/data/dazi.db`;上传图片存本机 `server/uploads/`。
- 定时任务(撮合、提醒、邀请到期)跑在服务进程内 —— **只能单实例**,不要起多份。

---

## 2. 环境变量(服务端)

| 变量 | 上线 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | **必须 `production`** | 不设则默认开发模式:开放 `/api/auth/dev-login`(可冒充任意用户)和 `/api/dev/*`(时间穿越),且后台密码退回 `admin123` |
| `ADMIN_PASSWORD` | **必填** | 后台登录密码,足够长的随机串。生产环境不设 **服务直接拒绝启动** |
| `PUBLIC_BASE_URL` | **必填** | 对外 HTTPS 地址(如 `https://dazi.example.com`),用于拼接图片绝对地址 |
| `WX_APPID` / `WX_SECRET` | 必填 | 微信登录与手机号验证;不配则生产环境登录不可用 |
| `TRUST_PROXY` | 放 Nginx 后 | 设 `loopback`,否则后台登录限流拿到的是代理 IP |
| `PORT` | 选填 | 默认 `3000` |
| `DB_PATH` | 选填 | 默认 `data/dazi.db`(相对 server 目录) |
| `UPLOAD_DIR` | 选填 | 默认 `uploads` |
| `ADMIN_DIR` | 选填 | 默认 `../admin`(server 要能读到 admin 目录才能托管后台) |
| `LOG_LEVEL` | 选填 | 默认 `info` |

可以放在 `server/.env`(KEY=VALUE,会自动加载,已存在的系统环境变量优先)。

## 3. 部署步骤(server + 后台)

```bash
# 1. 取代码(本发布分支)
git fetch origin claude/practical-hypatia-bsvys3
git checkout claude/practical-hypatia-bsvys3

# 2. 装依赖
cd server
npm install

# 3. 配置环境变量(见 §2),至少:
#    NODE_ENV=production ADMIN_PASSWORD=<随机串> PUBLIC_BASE_URL=https://<域名> WX_APPID=... WX_SECRET=...

# 4. 初始化数据
#    正式上线通常【不要】写演示数据 —— 空库首次启动会自动写入默认标签,直接启动即可。
#    只有需要演示数据(栗子、阿野、苍山看日出……)时才跑:
# npm run seed

# 5. 启动(正式用 pm2 / systemd 守护,保证崩溃重启)
npm start          # 监听 PORT(默认 3000)
```

6. **Nginx**:反代到 `PORT`,配好 HTTPS 证书;同时设 `TRUST_PROXY=loopback`。
7. **后台**:无需单独部署,浏览器打开 `https://<域名>/admin/`,用 `ADMIN_PASSWORD` 登录。

## 4. 小程序发布

1. 改 `miniprogram/config.js`:
   - `baseURL` → 你的 HTTPS 域名(如 `https://dazi.example.com`)
   - `devLogin` → `false`(改走 `wx.login → /api/auth/login`,不再自动登演示账号)
   - `subscribeTemplates` 的四个模板 id → 在小程序后台「订阅消息」申请后填入(留空则「开启提醒」只做提示)
2. 微信公众平台 → 开发设置 → 把域名加进 **request / uploadFile / downloadFile** 合法域名。
3. 微信开发者工具:导入 `miniprogram/` → 选正式 AppID → 上传 → 在后台提交审核、发布。
4. 账号认证、服务类目、手机号快速验证、隐私保护指引:见 README「上线前需要准备」。

## 5. 上线后自检(必做)

1. **看启动日志**,下面两条若还出现,说明环境变量没生效,停下排查,**不要放量**:
   - `未设置 ADMIN_PASSWORD，后台密码使用开发默认值 admin123`
   - `开发辅助接口已开启（/api/auth/dev-login、/api/dev/*）。部署时务必设置 NODE_ENV=production`
2. **健康检查**:
   ```bash
   curl https://<域名>/api/health
   # 期望:{"ok":true,"env":"production","wechat":"configured",...}
   ```
   `env` 必须是 `production`,`wechat` 应是 `configured`(不是 `dev`)。
3. **确认后门已关**:生产环境访问 `POST /api/auth/dev-login`、`/api/dev/clock` 应返回 404(`devTools` 已关闭)。

## 6. 冒烟清单(放量前手过一遍)

**服务端**:预发环境可先跑 `cd server && npm run smoke`(起临时服务、HTTP 走一遍主流程)。

**小程序真机**(本次改了 5 个小程序页面,⚠️ 云端测试环境没有微信开发者工具,这些务必真机点一遍):

- [ ] 登录 → 首页正常加载
- [ ] **H1(重点)**:当天下午发起撮合 → 后台「确认成局」→ 收到「撮合成功」→ 点「加入」能成功 → 凑齐后成群(不再一建即死)
- [ ] 发起页深夜(约 22 点后)在日期里选「今天」→ 自动跳「明天」且时间段可选(不是整排灰)
- [ ] 动态/广场:快速连点两条**不同帖子**的赞,两条都生效
- [ ] 群聊:未成群时进去显示「还差 N 人」,成群后再进会自动刷新进群
- [ ] 加入某局后,详情页状态/按钮正确、不闪
- [ ] AA:记账 → 标记「我已转账」→ 对方「确认收到」
- [ ] 开启「只参加同性局」后,广场/首页仍能看到混合局且能加入(M2)
- [ ] 后台:撮合池「确认成局」;轮播图编辑里选「不跳转」保存后确实无跳转(T1)

## 7. 本次产品口径(如不认可,这里回退)

这几条改动涉及产品判断,按「最贴合文档/隐私模型」的默认实现,若与你的预期不符可单独回退:

| 条目 | 现在的行为 | 想要另一种时 |
| --- | --- | --- |
| **H1** | 保留当天/短时撮合:邀请窗口随开场远近自适应(正常 12h,短时局缩到开场前 30 分钟);离开场不足 1 小时的不允许确认成局 | 想「干脆不做当天局」→ 改 `server/src/services/invites.js` 的 `lastCall()` 短路分支 |
| **M2** | 「只参加同性局」只约束**撮合**,不过滤浏览(否则广场几乎全空却又能手动加入,自相矛盾) | 想连浏览也只看同性 → 恢复 `squareCandidates` 的过滤,并同步收紧 join 逻辑 |
| **M3** | 放鸽子 2 次 = 真·停撮 **7 天**(兑现文档与通知里的「7 天」),7 天后信用显示「一般」 | 想停 30 天 → 改回 `computeCredit` 并把通知文案改成实际时长 |
| **L11** | 已结束的撮合局标题**不再**对非成员展示(对齐 README「撮合局只有成员能看」) | 想在别人主页展示「参加过的局」→ 回退 `profile.js` 的 recentEvents 过滤 |

> 另外验证为「无需改」的:L4(迟到打卡算迟到是有意设计且有测试)、L5(启动已对生产无密码拒启、并对 devTools 告警)、L10(CORS 反射当前不可利用,收窄需你的线上 Origin)。

## 9. 已知限制(上线须知)

摘自 README「现在还没有的」,放量前让团队知悉:

- 微信**订阅消息**和**内容安全**接口只留了位置、尚未真正调用;内容审核目前靠关键词。
- 群聊只支持**文字**,每 3 秒轮询刷新(没有 WebSocket)。
- 后台只有**一个共用密码**,没有分账号和操作日志。
- 定时任务在服务进程内 → **单机单实例**;上传图片存本机磁盘(扩展需接对象存储)。
- CORS 反射任意 Origin(当前不可利用:纯 Bearer、不带 cookie);若后台将暴露在公网,建议配白名单。
